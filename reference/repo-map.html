Repo map

What each file in ~/projects/others/ai-coding-crash-course/ is for, and where its code runs.

Paths in bold appeared in lesson 1. The rest are here so you can look up a file the moment a diff names it, and each will get its own lesson. For the journey a page takes through these files, see where code runs.

The app: app/

Path Holds Runs
app/routes.ts The route table: every address Cadence answers to, paired with its route file. A route file that is not listed here gives a 404. Server
app/routes/ Route files: 23 pages, one layout and four api.* files that answer requests without showing a page. Each page file holds a loader and a component. Server for loader and action.
Server then Browser for the component.
app/routes/layout.app.tsx The frame around most pages: the sidebar and the DevUI panel. The home, login and signup pages sit outside it. As any route file
app/root.tsx The outermost HTML shell that every page is placed inside. Server then Browser
app/components/ Reusable pieces of a page, such as the sidebar and the DevUI panel. ui/ inside it holds the basic building blocks (button, card, input and five more), copied in from shadcn/ui. Server then Browser
app/services/ Functions that read and write the database, one file per topic (users, courses, quizzes and so on). Most have their tests beside them in a *.test.ts file. Server
app/db/index.ts Opens data.db and hands out db, the connection the services use. Server
app/db/schema.ts The shape of every table: its name and its columns. Also the lists of allowed values, such as the three user roles. Server and Browser, because components import the role names from it
app/lib/session.ts
app/lib/validation.ts 		Who the current user is, kept in a cookie. Checks on what a form sent. Server by habit: only loaders and actions use them, but nothing enforces it
app/lib/*.server.ts Working out a visitor's country. Turning Markdown text into HTML. Server, enforced: the build refuses to send a .server file to a browser
app/lib/utils.ts
app/lib/ppp.ts 		Small helpers with no secrets in them: formatting a price, regional pricing. Server and Browser
app/app.css The app's colours and styling set-up. Browser
app/test/setup.ts Builds a throwaway database in memory for each test. Tests only

A name is not a route

File names like courses.$slug.tsx look as if they decide the address. They do not. That file handles /courses/:slug only because a line in app/routes.ts says so. A new route file does nothing until it is added there.

Beside the app

Path Holds
data.db Database The data itself: 17 tables of rows. data.db-wal and data.db-shm belong to it, so treat the three files as one. None of them is in git.
drizzle/ Migrations: numbered SQL files that build the tables one step at a time. Three so far. meta/ is the tool's own bookkeeping.
scripts/seed.ts The sample data: the users, courses and lessons you see in the app.
public/ Files sent to the browser exactly as they are: the icon and the course cover images.
.react-router/ Generated type files, the target of every ./+types/… import. Not in git. The dev server and npm run typecheck recreate them.
react-router.config.ts
tsconfig.json
drizzle.config.ts 		Settings. The first turns on building pages on the server. The second is why ~/ in an import means app/. The third tells the database tool where the schema, the migrations and data.db are.
request-logger/
lessons/ 		Not Cadence. A separate tool the course uses to record what Claude Code sends, and your saved copies of the course lessons.

Commands

Command What it does Changes
npm run dev Starts the server at localhost:5173. Ctrl+C stops it. Nothing
npm run db:generate Compares app/db/schema.ts with the migrations so far and writes a new migration file into drizzle/. Code
npm run db:migrate Applies to data.db any migration files it has not had yet. The cure for a no such column error. Database its tables
npm run db:seed Empties data.db, rebuilds its tables from the migrations and refills the sample data. Anything you added through the app is gone. Database everything
npm run test Runs every test once. Tests use a throwaway database in memory, not your data.db. Nothing
npm run typecheck Regenerates the route types, then checks the types of the whole project. Nothing you edit
npm run reset The course's own tool: rewinds your code to a lesson checkpoint. Uncommitted work is lost. It does not touch data.db, so run db:migrate or db:seed afterwards. Code

When the docs and the code disagree, trust the code

  • The README says React Router v7. package.json installs 8.3.0, so read the docs at reactrouter.com/8.3.0.
  • The README lists Ably for live presence. It is not installed.
  • Tutorials fetch a loader's result with useLoaderData(). Cadence never does: every component receives it as the loaderData prop.
